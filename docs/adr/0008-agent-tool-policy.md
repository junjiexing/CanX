# ADR-0008：Agent 与统一 Tool 安全边界

- 状态：接受
- 日期：2026-09-14

## 决策

CanX 的 LLM Agent 只能通过统一 `ToolRegistry` 影响应用状态。模型不能直接持有下载器、播放器、
插件 runtime、文件系统、网络客户端或凭证存储对象。用户界面、插件和 Agent 共用相同 Tool
实现，但调用主体、授权和审计上下文彼此独立。

每个 Tool 使用固定名称、版本、风险级别以及输入/输出 JSON Schema。Registry 在调用前验证输入，
执行超时与取消，在调用后验证输出并限制返回大小。写操作可携带幂等键；审计记录调用主体、Tool、
风险、关联链、耗时和结果，但不记录参数、返回正文、凭证或幂等键原文。

Agent 默认只能执行只读 Tool。网络、本地写入和破坏性操作默认必须由 Policy grant 或当前操作的明确
用户批准放行。用户可在 Agent 设置中开启“自动批准工具调用（YOLO 模式）”，从下一次发送消息起
自动批准本次运行中的 Tool 调用；此选项默认关闭，模型不能通过 `settings.set` 修改。
自动批准仅跳过逐次确认，Schema、超时、审计和各 Tool 的领域校验仍然生效。
批准不能被模型文本、网页内容或插件返回值生成。凭证始终由宿主通过
`CredentialRef` 使用，不进入模型上下文。

插件的安装期权限批准不能替代逐次确认。插件调用 Tool 时只允许只读 Tool 和一份宿主固定的可逆
播放/下载控制白名单；其余 Tool 即使出现在 manifest `tools.invoke` scope 中也会被拒绝。

风险级别按“最坏后果”而不是操作动词确定。能改变凭证流向、代码加载或落盘位置的设置
（LLM `baseUrl`、下载目录、mpv 高级选项）只允许用户在设置页修改；aria2 选项只接受自动化白名单；
mpv 高级选项与运行时 property 写入拒绝加载脚本、打开 IPC 或读写任意文件的选项；Agent API Key
绑定保存时的 endpoint origin，地址变化后必须重新录入。

首期使用单 Agent、有界 tool loop：限制轮次、输入输出大小、超时和 Token 预算，支持用户取消。
媒体网页、字幕、插件内容和 Tool 输出均标记为不可信数据，不能改变系统规则、授权或预算。

## LLM Provider 边界

Provider 接口与具体协议分离。首个适配器实现 OpenAI-compatible HTTP API，并允许配置私有网关
Base URL；API Key 只保存在平台凭证库。后续本地模型复用相同消息、Tool 和流式事件契约。
CanX 不依赖 provider SDK 的反射模型，以保持 NativeAOT 和裁剪兼容。

## Plugin Workspace

Agent 只能在宿主创建的独立工作区内创建和修改插件。所有相对路径都进行 canonical path、符号链接
和大小限制检查；构建、测试和 QuickJS 试运行通过固定命令执行，不提供任意 shell。安装前展示源码、
权限和测试结果 diff，并要求用户批准，失败版本不得替换当前插件。

## 结果

- 新 Tool 必须提供 Schema、风险和覆盖测试。
- Tool 调用可由 UI、插件和 Agent 复用，但授权上下文不可互相继承。
- 任何自动搜索、播放、下载或插件修改流程都必须可取消、可审计，并在预算内终止。
- 进程级插件隔离和其他平台发布验证仍属于阶段 7；它不放宽本 ADR 的消息与权限边界。
